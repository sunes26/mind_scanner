# 블로그 글 작성 지침

속마음 스캐너 블로그 글을 쓰거나 고칠 때 따르는 규칙입니다. 목적은 하나입니다. 검색해서 들어온 사람이 "이 글 덕분에 궁금한 게 풀렸다"고 느끼게 하는 것.

## 1. 파일 규칙

- 글 하나 = `app/blog/posts/<slug>.tsx` 파일 하나. slug·제목·설명·날짜는 `app/blog/blogData.ts`에 이미 있습니다(수정하지 말 것).
- 파일은 정확히 두 가지를 export 합니다.

```tsx
import {
  Summary, H2, H3, P, Callout, List, ChatExample, CompareTable,
  PostImage, PostLink, SampleLink, Sources,
  type PostFaqItem,
} from '@/components/blog/PostKit'

export const faq: PostFaqItem[] = [
  { q: '질문?', a: '두세 문장으로 끝나는 답.' },
]

export default function Post() {
  return (
    <div className="space-y-6">
      <Summary>
        <p>글 전체의 답을 2~4문장으로.</p>
      </Summary>
      <H2 id="section-id">소제목</H2>
      <P>본문</P>
    </div>
  )
}
```

- 사용할 수 있는 것: `components/blog/PostKit.tsx`의 컴포넌트, 기본 HTML 태그(`strong`, `em`, `li`, `code`, `br`), Tailwind 클래스. 새 컴포넌트·새 의존성·`'use client'`는 쓰지 않습니다.
- FAQ는 `faq` 배열로만 넘깁니다. 본문 안에 FAQ 섹션을 직접 만들지 마세요(페이지가 자동으로 렌더링하고 JSON-LD로도 출력합니다). 3~5개.
- `<li>`는 `<List>` 안에 넣습니다. JSX 텍스트의 따옴표는 `"` 대신 `“ ”` 또는 `&quot;`를 써서 lint 오류를 피합니다. 중괄호·꺾쇠는 문자열로 감쌉니다.
- 제목(h1), 날짜, 작성자, 관련 글, 하단 CTA는 페이지가 그립니다. 본문에 넣지 마세요.

## 2. 분량과 구조

- 본문 한글 기준 **공백 제외 3,000자 이상**(FAQ 제외). 늘리기 위해 같은 말을 반복하지 말고, 사례·예시 대화·구체적인 방법으로 채웁니다.
- 첫머리 `<Summary>`에 결론을 먼저 씁니다. 검색 사용자와 AI 요약 엔진 모두 여기를 봅니다.
- `H2`는 5~8개. 가능하면 독자가 검색할 법한 질문·구체적 문장으로 씁니다("답장이 늦으면 관심이 없는 걸까?"). 제목에 이모지를 쓰지 않습니다.
- 각 `H2` 바로 아래 첫 문단은 그 소제목에 대한 답을 혼자서도 이해되게 씁니다.
- 표(`CompareTable`), 목록(`List`), 예시 대화(`ChatExample`)를 섞되, 박스만 나열하지 말고 문단으로 설명합니다.
- 이미지는 글마다 **2~3장**. 아래 "이미지 목록"에 있는 파일만 씁니다. 첫 이미지는 그 글의 `cover`(blogData.ts)와 같은 것을 `<Summary>` 바로 아래에 둡니다. `alt`는 그림 내용을 문장으로 설명합니다.
- 다른 글로 가는 `PostLink`를 본문 흐름 속에 2~4개, 샘플 리포트로 가는 `SampleLink`를 1개 넣습니다. 링크는 발행일이 이 글보다 이르거나 같은 글로만 겁니다(예약 글은 발행 전까지 404).

## 3. 사실 규칙 (가장 중요)

이 사이트는 지어낸 통계 때문에 신뢰를 잃었습니다. 다음을 지킵니다.

- **숫자를 지어내지 않습니다.** "AI가 N만 건을 분석한 결과", "호감도 90점 이상인 사람의 평균 답장 시간은 5~10분", "이모티콘 60% 법칙" 같은 문장은 전부 금지. 속마음 스캐너는 대화를 저장하지 않으므로 이런 통계를 가질 수 없습니다.
- 경험칙은 경험칙이라고 씁니다. "~인 경우가 많습니다", "~로 읽히기 쉽습니다". 단정("~하면 호감 확정")은 금지.
- 사용자 후기, 별점, "N명이 사용" 같은 것을 만들지 않습니다.
- 심리학을 인용할 때는 실제로 존재하고 널리 알려진 개념만, 이름을 밝혀서 씁니다. 확실하지 않으면 인용하지 않습니다. 쓸 수 있는 예:
  - 사회적 침투 이론(Altman & Taylor, 1973): 관계가 깊어질수록 자기 노출의 폭과 깊이가 커진다.
  - 자기 노출의 상호성: 한쪽이 속 얘기를 하면 상대도 비슷한 수준으로 답하는 경향.
  - 단순 노출 효과(Zajonc, 1968): 자주 접할수록 호감이 생기기 쉽다.
  - 호감의 상호성: 나를 좋아하는 사람을 좋아하게 되는 경향.
  - 지각된 반응성(Reis & Shaver의 친밀감 과정 모델): 상대가 나를 이해·인정·배려한다고 느낄 때 친밀감이 커진다.
  - 관계 연결 시도(bids for connection, John Gottman): 사소한 말 걸기에 반응해 주는지가 관계 만족과 관련된다.
  - 애착 이론(Bowlby; 성인 애착은 Hazan & Shaver, 1987): 불안형은 연락 공백에 민감하고 회피형은 거리를 두는 경향.
  - 간헐적 강화(Skinner): 보상이 불규칙할수록 행동이 잘 사라지지 않는다.
  - 텍스트 대화에서 비언어 단서를 이모티콘 등이 대신한다는 것(컴퓨터 매개 커뮤니케이션 연구; Walther의 사회정보처리 이론).
  - 반추(rumination): 같은 걱정을 되풀이하는 사고 습관.
  연구의 구체적 수치·실험 세부는 확실히 아는 경우가 아니면 쓰지 않습니다. 인용한 개념은 글 끝 `<Sources>`에 저자·연도로 적습니다(URL은 확실할 때만).
- **점수 계산식은 비공개입니다.** 종합 애정 지수, 관심도 지수, 항목별 진단의 높음·보통·낮음, 대화 성향 유형 분류에 쓰이는 가중치·배점·상한·기준값·공식은 글에 절대 쓰지 않습니다. 코드(`server/scoring`)에서 볼 수 있더라도 인용하지 않고, 샘플로 역산한 계산 예시("84점 = 49 + 5.3 + …")도 쓰지 않습니다. 쓸 수 있는 것은 (1) 점수가 살펴보는 여섯 영역의 이름과 정성적 설명, (2) 각 통계를 브라우저에서 세는 규칙(§4의 내용)까지입니다. 공개하지 않는 이유를 물으면 "점수를 꾸미기 어렵게 하고, 가중치를 계속 조정하기 때문"이라고 그대로 씁니다. 샘플 리포트의 관심도 지수 숫자도 인용하지 않습니다.
- 카카오톡 메뉴 이름은 버전·기기마다 다릅니다. 경로를 설명하되 "버전에 따라 메뉴 이름이 조금 다를 수 있습니다"를 덧붙입니다.
- 다른 회사 서비스를 이름 들어 평가하지 않습니다.
- 글을 쓴 사람은 속마음 스캐너를 만든 1인 개발자(Oceancode)입니다. 자기 도구를 설명할 때는 만든 사람 입장임을 숨기지 않습니다. 광고 문구("지금 바로!", "완벽 분석")는 쓰지 않습니다.

## 4. 속마음 스캐너가 실제로 하는 일

제품을 언급할 때는 아래 내용과 어긋나면 안 됩니다. 아래에 없는 기능은 없다고 보면 됩니다.

**입력**
- 카카오톡에서 내보낸 `.txt` 파일만 받습니다. 최대 50MB. 글자 수가 30만 자를 넘으면 최근 30만 자만 사용합니다.
- 인식하는 형식: PC 내보내기(`2026년 9월 1일 오후 7:12, 이름 : 내용`), 모바일(`2026. 9. 1. 오후 7:12, 이름 : 내용`), 대괄호형(`[이름] [오후 7:12] 내용`).
- 메시지가 20개 미만이거나 참여자가 2명 미만이면 분석하지 않습니다.
- 참여자가 3명 이상이면 메시지를 가장 많이 보낸 두 사람만 고르고, 그 두 사람의 메시지만 남기고 나머지는 분석 전에 버립니다. 아래의 모든 통계(메시지 비율은 합이 100%, 하루 평균, 답장 간격, 시간대 그래프)와 점수·진단이 그 두 사람의 메시지만으로 계산됩니다. 그래도 둘이 서로에게 한 말인지는 알 수 없으므로 단톡방용 도구가 아닙니다.
- 한 메시지 안에서 줄을 바꿔 쓴 경우(날짜·이름이 없는 이어지는 줄)는 앞 메시지에 이어 붙여 전체를 하나의 메시지로 읽습니다.
- 이름은 20자까지 허용하고(넘으면 닉네임 오류), `&`나 `'` 같은 기호가 들어 있어도 정상 처리합니다.
- 업로드 검사에서 "위험한 코드" 오류가 나는 것은 파일에 실제 HTML 마크업(script, iframe, object, embed 태그, 또는 on…= 이벤트 속성이 붙은 태그)이 있을 때뿐입니다. 링크 주소(`utm_content=` 등)는 걸리지 않습니다.
- 내용 전체가 정확히 "사진"(또는 "사진 N장"), "동영상", "이모티콘"(카카오 이모티콘 스티커)인 메시지, 파일 전송, 삭제된 메시지, 입장/퇴장 알림은 시스템 메시지로 보고 통계에서 뺍니다. "어제 찍은 사진"처럼 문장 끝이 "사진"인 메시지는 평범한 메시지입니다. 따라서 카카오 이모티콘 스티커 사용량은 세지 못하고, 글자로 입력한 이모지(😊)만 셉니다.

**브라우저에서 계산하는 통계(사람별)**
- 메시지 수와 비율, 평균 글자 수
- 대화 중 답장 간격의 중간값: 상대 메시지 바로 다음에 내가 보낸 메시지까지의 간격 가운데 3시간 이하인 것만 모아 중간값을 냄. 3시간을 넘긴 답은 느린 답장이 아니라 새 대화의 시작으로 봄. 같은 분 안의 답장은 0분(파일 시각이 분 단위). 이 답장들 가운데 5분 안에 온 것의 비율도 셈.
- 평균 답장 시간(예전 방식, 지금도 계산은 함): 같은 간격을 24시간 초과만 빼고 평균. 리포트 상단 카드에는 더 이상 쓰지 않음. 샘플의 예전 카드 값은 41분이었음.
- 먼저 말 건 횟수(선톡): 3시간 이상 공백 뒤 첫 메시지를 보낸 횟수
- 대화의 마지막 메시지를 보낸 횟수: 그 뒤로 3시간 넘게 공백이 이어진 메시지를 보낸 횟수(파일의 맨 마지막 메시지는 제외)
- 질문 횟수(물음표 기준), 느낌표 횟수
- 이모지 수(이모지 한 개를 1로 셈. 샘플: 지우 12개, 민준 5개), 하트 이모지 수, 애정 표현 단어 수(사랑·좋아·보고싶 같은 단어 목록 일치 횟수. 진짜·너무 같은 강조어는 목록에 없고, 겹치는 단어는 한 번만 셈)
- 웃음 표현 횟수: ㅋㅋ·ㅎㅎ가 2글자 이상 이어진 덩어리의 개수 (ㅋ의 길이는 재지 않음)
- 약속을 꺼낸 메시지 수: "만나", "볼까", "갈래", "언제 시간" 같은 표현이 들어간 메시지 수(실제로 만났는지는 모름)
- 존댓말로 끝난 메시지 비율: "~요", "~니다", "~세요" 같은 어미로 끝난 메시지의 비율
- 심야 메시지 수(밤 11시~새벽 2시), 연달아 보낸 횟수(1분 안에 3개 이상 잇달아 보낸 묶음의 수)
- 대화 기간을 시간상 반으로 나눈 앞·뒤 메시지 수
- 시간대별 대화량(새벽/오전/오후/저녁), 대화 기간(일수), 대화가 있었던 날 수, 하루 평균 메시지 수

**서버에서 계산하는 점수와 진단(규칙 기반, AI 없음)**
- 브라우저는 위 통계 가운데 개수와 비율만 서버로 보냅니다. 두 사람은 A, B로만 구분되고 이름과 대화 내용은 포함되지 않습니다. 서버가 돌려준 문장에 이름을 채워 넣는 일은 브라우저가 합니다.
- 서버는 고정된 규칙으로 다음을 계산합니다. 같은 파일은 항상 같은 결과가 나오고, 결과는 거의 바로 나옵니다(예전의 10~30초 대기 없음).
  - 종합 애정 지수(0~100)와 관계 라벨
  - 관심도 지수
  - 항목별 진단 여섯 개: 주고받는 균형, 답장 반응, 대화 참여, 감정 표현, 연락의 꾸준함, 최근 흐름. 각각 높음/보통/낮음과 한 줄 설명.
  - 대화 성향 유형(사람별 하나): 질문형, 공감형, 리드형, 장문형, 칼답형, 마이페이스형, 올빼미형, 표현형, 실행형, 안정형 등 열두 개 안팎
  - 관계 균형 진단(최대 네 개): 누가 대화를 시작하는지, 누가 질문하는지, 말의 양, 대화의 마지막, 답장 속도, 말투, 최근 흐름 등
  - 맞춤 조언(사람별)
- 계산식·가중치·기준값은 비공개입니다(§3). 글에는 위 이름과 정성적 설명만 씁니다.
- 문장은 미리 써 둔 것 가운데 규칙으로 고르므로 다소 일반적으로 느껴질 수 있고, 연애 관계를 기준으로 쓰여 있습니다.

**리포트 화면**
- 종합 애정 지수 + 관계 라벨. 참고용이며 정밀 측정이 아닙니다.
- 하루 평균 메시지, "대화 중 답장" 카드(두 사람의 대화 중 답장 간격 중간값을 평균한 값), 메시지 비율 도넛("투머치 토커"), 24시간 활동 패턴 그래프, 관심도 지수
- 답장 패턴 정밀 분석(지우/민준 토글로 한 사람을 선택, 사람별 여섯 칸): 메시지 비중, 평균 글자 수, 질문 횟수, ㅋㅋㅋ 사용, 먼저 말 건 횟수(선톡), 심야 메시지. 하트 이모지·애정 표현 단어·느낌표·약속 메시지·존댓말 비율은 화면에 칸으로 표시하지 않습니다.
- SECRET REPORT: 두 사람의 대화 성향 분석 → 항목별 진단 → 관계 균형 진단 → 맞춤 조언 → AI 한 줄 코멘트 버튼
- AI 코멘트(선택): 리포트 맨 아래 "AI 코멘트 받기" 버튼을 눌렀을 때만, 서버로 보냈던 것과 같은 숫자 통계가 API 모니터링 도구(Spanlens)를 거쳐 OpenAI API(gpt-4o-mini)로 전달되고 3~4문장짜리 코멘트가 돌아옵니다. 대화 내용과 이름은 전송되지 않습니다. 코멘트는 누를 때마다 달라질 수 있지만 점수와 진단은 달라지지 않습니다.

**없는 기능**: 읽음 시간/읽씹 여부(내보내기 파일에 읽음 정보가 없음), 프로필·상태메시지 분석, 시간대별 답장 속도, 감정 변화 그래프, ㅋ 개수 측정, 유료 이모티콘 구분, "상호 인식 분석"(두 사람이 서로를 어떻게 생각하는지 — 대화 기록으로 알 수 없는 것이라 삭제함), AI가 대화를 읽고 쓰는 해석. "AI의 맞춤 조언"은 규칙 기반 "맞춤 조언"으로 바뀌었습니다.

**데이터 처리**
1. 파일은 브라우저에서 읽고 통계도 브라우저에서 계산합니다. 대화 내용과 참여자 이름은 브라우저 밖으로 나가지 않습니다.
2. 속마음 스캐너 서버로는 숫자 통계(개수와 비율, 두 사람은 A/B)만 전송됩니다. 서버는 이를 규칙으로 계산해 점수와 진단을 돌려줍니다. AI를 쓰지 않습니다.
3. "AI 코멘트 받기" 버튼을 누른 경우에만 같은 숫자 통계가 Spanlens를 거쳐 OpenAI API(gpt-4o-mini)로 전달됩니다. OpenAI 등 처리 업체는 각자 정책에 따라 요청 기록을 일정 기간 보관할 수 있습니다.
4. 속마음 스캐너는 통계와 결과를 자체 DB나 파일로 저장하지 않습니다. 회원가입도 없습니다. 결과는 화면에만 있고 페이지를 닫으면 사라집니다.
5. 그래도 숫자 통계는 서버로 가므로 "모든 처리가 기기 안에서" 같은 표현은 쓰지 않습니다. 대화 내용이 전송되지 않으므로 "민감한 내용을 지우고 올리라"는 안내는 더 이상 하지 않습니다(대화 원문을 받는 다른 서비스에 대한 일반 조언으로는 쓸 수 있음). 상대방이 모르는 채로 그 사람의 대화가 분석된다는 점은 여전히 밝힙니다.
6. 무료이며 광고(쿠팡 파트너스)가 붙습니다.

**샘플**: `/sample` 페이지에 가상의 두 사람(지우, 민준)의 3주(21일)치 대화 164개로 만든 예시 리포트가 있습니다. 종합 애정 지수 82, 라벨 "서로 호감이 분명한 사이", 하루 평균 메시지 8, 대화 중 답장 약 3분. 지우는 "마음을 말로 하는 표현형", 민준은 "약속을 만드는 실행형". 항목별 진단은 다섯 개가 높음, 최근 흐름이 낮음. 관계 균형 진단에 "뒤쪽 절반은 앞쪽보다 메시지가 31% 적습니다", "질문의 69%가 민준님에게서" 등이 나옵니다. 샘플의 관심도 지수 숫자는 글에 인용하지 않습니다.
